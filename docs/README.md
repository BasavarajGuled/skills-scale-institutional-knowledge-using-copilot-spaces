# OctoAcme Project Management Docs

This README is the entry point to OctoAcme's project management guidance. It summarizes the project lifecycle and links to the detailed process documents below.

## Project management processes

OctoAcme follows a lightweight, iterative lifecycle: initiate work by validating the business need, aligning stakeholders, and defining measurable success criteria; then plan approved initiatives into prioritized, estimable increments with acceptance criteria, milestones, a Definition of Done, and documented risks and dependencies. During execution, teams track work on a project board, coordinate through regular check-ins, review and test small changes, monitor delivery signals, and escalate blockers through the agreed path.

The Project Manager coordinates delivery, schedules, risks, resources, and communications; the Product Manager defines outcomes, prioritizes work, and measures success. Developers implement and test increments, QA validates quality and acceptance criteria, and stakeholders provide input and approvals. Regular team standups, delivery syncs, PM–Product Manager alignment, and stakeholder updates keep progress, risks, blockers, and decisions visible.

Quality is integrated throughout delivery: small pull requests include issue links and acceptance criteria, automated tests and linting run in CI, and changes receive review before merging. Teams use unit, integration, and critical-flow smoke tests as appropriate, security scanning, and manual QA when needed. Releases require readiness checks, release notes, deployment verification, and rollback or mitigation planning. Retrospectives after sprints, releases, milestones, or incidents convert lessons into owned, trackable improvements.
